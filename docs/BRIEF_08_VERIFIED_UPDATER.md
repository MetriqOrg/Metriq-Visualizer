# Brief 08 — Verified updater security review

Implemented on `feat/updater` from `release/1.13-rollback` (`824c2bb`). The v1.12.8 updater and tests were read-only references. The original central layout, transport, panels and styles are unchanged. The only controls added are Help → **Check for Updates...** and one reusable, non-modal 440 px dialog. The dialog contains the daily-check setting and an explicit **Download, install and quit** confirmation button; Close is the default button.

| Required boundary | Implementation and evidence |
| --- | --- |
| HTTPS, approved repository, stable release | Exact `https://api.github.com/repos/MetriqOrg/Metriq-Visualizer/releases` metadata endpoint and exact numeric asset API endpoints. No credentials, ambient proxies or redirects. Both `draft` and `prerelease` must explicitly be false. Stable versions must exceed the running version. Tests reject foreign/ambiguous URLs, prereleases, drafts and downgrades. |
| Compatible macOS app ZIP and digest | Only documented Metriq macOS filenames with explicit arm64, x86_64 or universal architecture qualify; source/Windows/unknown-architecture assets fail. SHA-256 and positive bounded asset size are mandatory. Downloads must match both size and digest, and extraction rehashes the archive before opening it. Tests cover wrong assets, digest mismatch, archive tampering and oversize/truncated downloads. |
| Safe bounded extraction | New private staging directory; preflight every entry. Reject absolute paths, `..`, backslashes, drive syntax, control characters, Unicode/case path collisions, special files, encryption and writes through symlink ancestors. Framework symlinks are created last and must resolve to existing locations inside the sole top-level .app; escaping, broken or cyclic links fail. Limits: 1 GiB download, 4 GiB expanded bytes, 30,000 entries, 200:1 compression above 1 MiB, 2 MiB metadata, 4 KiB symlink targets. Executable bits are preserved; privileged bits are removed. Validated `__MACOSX` metadata is discarded. Tests cover malicious paths, links, executable modes, count, expanded-size, download, metadata and compression limits. |
| Expected bundle and newer version | Require `org.metriq.visualizer` and a bundle short version matching the selected release and exceeding the running version. Check the actual Mach-O executable architecture with the trusted system `lipo`, and verify bundle integrity with `codesign --verify --deep --strict`. Neither tool executes the downloaded program. Tests cover identity/version mismatch, downgrade, signature failure and incompatible executable architecture. |
| Consent and deferred installation | No download/staging without `confirmed=True`, set only by the explicit dialog button. Prepare and verification run on a worker thread; closing the main window is deferred while preparation is active. Launch the original installed executable in helper-only mode with an independent PyInstaller environment. This path exits before importing the UI. The helper waits for the original PID to disappear, takes an exclusive target lock, rechecks versions, signature and complete tree digests, then performs Darwin `renamex_np(RENAME_SWAP)` on the same filesystem. The downloaded application is never launched by the updater. Tests cover declining, consent gating, non-blocking UI, helper-only entry, exit waiting, tampering and native exchange. |
| Rollback and failure containment | Atomic exchange is the final fallible install operation: both bundle paths remain present. The complete original app remains at `<app parent>/.metriq-update-<id>/<app name>.app` for manual rollback. Errors before exchange leave the installed tree unchanged. Unsupported exchange volumes fail closed. A real native-exchange test abruptly exits the helper afterward and verifies that both apps remain present. Other tests cover launch failure, exchange failure, bad downloads and installed-version changes. |
| Daily silent startup check | A 4-second Qt timer checks only frozen macOS app launches. A persisted timestamp is claimed under an exclusive settings lock before HTTP, including offline attempts. Subsequent startup attempts within 24 hours are skipped; clock rollback also suppresses them. The dialog checkbox persists opt-out. HTTP uses a daemon worker, an 8-second timeout and bounded metadata. Offline/errors/no update are silent; an available update shows only the non-modal dialog and never downloads. Tests cover persistence, concurrent claims, opt-out, offline silence, throttling, a responsive GUI while HTTP is suspended, and visible unclipped confirmation text. |
| No telemetry | Requests contain only fixed GitHub API headers and repository URLs, without app version, credentials, user/session/device identifiers or uploaded data. There are no analytics, third-party requests or automatic error reports. Helper failures write a local `failure.txt` in the staging folder. |

The release builder now stamps the bundle ID and both version fields from `VERSION.txt`, then ad-hoc signs after changing the plist. Tests preserve other metadata and stop the build on signing failure.

## Threats considered and remaining limits

Considered hostile release metadata, source/wrong-CPU archives, transport redirection and credential leakage, archive tampering, path and symlink escapes, Unicode/case collisions, ZIP bombs, wrong bundle identity, downgrade/replay, staging changes while waiting, concurrent updaters, PID reuse, offline launches, accidental confirmation, read-only targets, and helper interruption. PID reuse can delay or abort installation, never force it early. Pre-existing updater processes serialize and refuse if their expected installed tree has changed.

* **Strict API-only delivery:** GitHub can return asset bytes directly or redirect the asset API request. The brief's strict host restriction is enforced, so redirected downloads are refused and cannot currently install. Supporting GitHub's asset CDN needs an explicitly approved host policy. See [GitHub's release-asset API documentation](https://docs.github.com/en/rest/releases/assets#get-a-release-asset).
* **Publisher trust:** SHA-256 binds downloaded bytes to authenticated GitHub metadata; it is not an independent publisher signature. Ad-hoc codesign checks integrity, without a pinned Apple Team ID or notarization requirement. A compromised repository/publisher can publish malicious code with a valid digest. Developer ID pinning or independently signed update manifests remains open.
* **Local trust:** A hostile process with the same user's permissions, or root, can alter updater code, manifests or the filesystem between checks. Private staging, full tree digests and locks reduce accidental/inter-process races; they do not isolate a compromised user account.
* **Recovery:** Rollback is manual and retained in a hidden sibling folder; staged failures and rollback bundles are not automatically deleted. The updater does not relaunch the new app. Atomic exchange prevents an empty installed path on process interruption; storage corruption, catastrophic power-loss durability and hardware failure are outside the tested guarantees. Volumes without swap support refuse installation. See [Apple's swap-renaming support](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsswaprenaming).
* **Packaged distribution:** Native exchange and the helper entry point were exercised locally. A complete new signed/notarized distribution was not built or installed over a real running app, and no live release or download endpoint was called. Detached frozen-helper configuration follows [PyInstaller's subprocess guidance](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses-that-outlive-the-application-process).

## Verification

Run with `/Users/macaroon/Developer/MV/.venv/bin/python`, `PYTHONDONTWRITEBYTECODE=1`, and `pytest -n 2 -q`. **96 tests passed** (including the original 31). All updater HTTP is mocked, and unexpected opener calls fail tests. Native filesystem exchange uses temporary synthetic app bundles. The UI is exercised with Qt's offscreen platform, including a rendered-dialog inspection. `git diff --check` and parsing of all changed Python modules are also checked.

Observed failing assertions before their fixes for permissive asset selection, case-insensitive symlink ancestors, the earlier shell-helper signal race, and clipped confirmation text. The broader port/security coverage was added alongside implementation; it is not claimed as an entirely red-first TDD run.
